# EcommerceSymfony Project

## 📖 Overview

This is a robust, multi-tenant E-commerce and Point of Sale (POS) application built with **Symfony 6.4**. It leverages **API Platform** for exposing a rich set of REST/GraphQL APIs and uses a Clean Architecture-inspired pattern with distinct **Use Cases** and **Services**.

The application is designed to handle complex business logic including:
-   **Multi-tenancy**: Dynamic database switching per tenant.
-   **E-commerce**: Product management, carts, orders, and shipping.
-   **Point of Sale (POS)**: Cash register management (`Caisse`), transactions.
-   **Internationalization**: Built-in translation system for dynamic content (using DeepL/Google Translate integrations).
-   **Integrations**: Payment gateways (Stripe, Square), Shipping (EasyPost), and external sync (Gemsuite).

## 🏗 Architecture

The project follows a structured approach to separate concerns:

### 1. **Core Layers**
-   **Entities (`src/Entity`)**: The core domain models. Most entities are implement `TranslatableInterface` for multi-language support.
-   **Repositories (`src/Repository`)**: Data access layer extending Doctrine repositories.
-   **Use Cases (`src/UseCase`)**: Contains the business logic of the application. Each directory groups specific use cases (e.g., `OrderUseCase`, `ProductUseCase`), promoting a command-oriented approach.
-   **Services (`src/Services`)**: Infrastructure and domain services. Includes external API integrations (`StripePaymentService`, `EasyPostService`), multi-tenancy logic (`TenantConnectionManager`), and helper utilities.
-   **Controllers (`src/Controller`)**: Entry points for the application, largely dealing with API Platform resources and some custom endpoints.

### 2. **Multi-Tenancy**
The application uses a dynamic client connection listener strategy:
-   **TenantConnectionManager**: Manages database connections dynamically based on the current tenant.
-   **TenantUserProvider**: Handles user authentication scoped to the active tenant.
-   **Security**: The `api` firewall is stateless and JWT-based, ensuring secure tenant access.

## 🚀 Key Features

### 🛒 E-commerce & Orders
-   **Product Catalog**: Manages Products, Variants (`ProductVariant`), Options (`ProductOption`), and Collections.
-   **Order Processing**: Complete flow from `Cart` to `Order`, including tax calculation (`OrderTax`) and shipping (`ShippingOrder`).
-   **Dashboards**: Elaborate statistical analysis found in `StatistiqueUseCase` and `CommandeDashboardUseCase`.

### 💳 Payments & POS
-   **Gateways**: Integration with **Stripe** and **Square**.
-   **Cash Register**: `Caisse` and `TransactionCaisse` entities manage physical store operations (Opening/Closing, Cash details).

### 🌍 Internationalization (i18n)
-   Entities like `Product`, `Banniere`, `BaniereStatique` have associated `*Translation` entities.
-   **Translation Services**: `DeepLTranslateService` and `GoogleTranslateService` allow for automated content translation.

### 🚚 Logistics
-   **Shipping**: Integration with **EasyPost** (`EasyPostConfiguration`) for label generation and tracking.
-   **Inventory**: `InventoryMovements` and `StockEvolution` track stock changes over time.

### 🔌 External Integrations
-   **Gemsuite**: A dedicated `GemsuiteImporterService` handles data synchronization with the Gemsuite platform.
-   **Webhooks**: `GemsuiteJwtAuthenticator` secures incoming webhooks from external systems.

## 🛠 Technology Stack

-   **Framework**: Symfony 6.4
-   **API**: API Platform 3
-   **ORM**: Doctrine ORM
-   **Database**: PostgreSQL (Driver `pdo_pgsql`)
-   **Admin**: EasyAdmin Bundle

## ⚙️ Configuration

### Environment Variables (.env)
The application relies on several environment variables for configuration. Ensure these are set in your `.env.local` or `.env` file:
-   `DATABASE_URL`: Primary database connection.
-   `STRIPE_SECRET_KEY`, `SQUARE_ACCESS_TOKEN`: Payment gateway credentials.
-   `EASYPOST_API_KEY`: Shipping provider key.

### Security
Security is configured in `config/packages/security.yaml`.
-   **Firewalls**:
    -   `api`: Main API firewall (JWT blocked).
    -   `gemsuite_api`: Specific webhook access.
    -   `main`: Standard web access.
-   **Roles**: `ROLE_ADMIN`, `ROLE_USER_INTERNET`, `ROLE_USER_POS`.
